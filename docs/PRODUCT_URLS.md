# Адреса каталога

- Бренд: `/<brands.slug>/`, например `/yves-saint-laurent/`.
- Аромат: `/<brands.slug>/<название>.html`, например `/dior/sauvage.html`.

Название получается из существующего SKU удалением начального slug бренда
(включая повторный префикс). Если префикса нет, используется весь SKU.
База, SKU, ID и привязки фотографий не изменяются. Дубли адресов запрещены.

Старые `index.php?sku=...` и `/бренд/аромат/` перенаправляются 301 на `.html`.
Старый `?brand=...` перенаправляется на `/бренд/`, с сохранением пагинации
и поискового запроса, если они присутствуют. Неверные бренд/аромат возвращают 404.
В HTML указывается canonical, навигация и изображения имеют пути от корня.

Файлы `.html` с PHP-кодом не создаются. Apache переписывает такие URL на
общий корневой `index.php` через выделенный блок `.htaccess`. Старое содержимое
этого файла сохраняется; перед изменением делается закрытая резервная копия.
Изменение конфигурации nginx и перезапуск сервера не требуются в стандартной
nginx+Apache конфигурации Hestia. Для страниц брендов остаются каталоги
с символьной ссылкой `../index.php`; старые каталоги ароматов обеспечивают 301.

Скрипт публикации читает актуальные публичные ссылки каталога и проверяет
уникальность. Неизвестные файлы маршрутов не перезаписываются. Приложение
остаётся одним PHP-файлом без копирования кода по карточкам.

Проверки: tests/Feature/single_php.py — все 63 карточки, страницы брендов,
canonical и 301/404. После деплоя проверяются реальные HTTPS-адреса.
